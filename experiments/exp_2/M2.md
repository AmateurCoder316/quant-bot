# EXP-2-M2

## Why M2 exists

EXP-2-M1 improved the research architecture but still used mostly hand-selected model hyperparameters. Its 2025 execution tuning failed decisively: the selected top-1% rule returned -6.90% after costs, PF 0.53, average trade -0.262%, and only 1/12 positive months.

M2 keeps the EXP-2 event dataset, triple-barrier labels, overlap-aware weights, cost model and execution simulator. It changes the model-training process itself.

## Core hypothesis

A properly optimized, chronologically validated heterogeneous ensemble may rank economically successful events materially better than M1's hand-configured stack.

All model-family and hyperparameter selection occurs inside 2023-2024. 2025 is excluded from model search and is used only after the model is frozen.

## Training lab

Six model families are searched independently:

1. scikit-learn HistGradientBoosting
2. scikit-learn ExtraTrees
3. regularized Logistic Regression
4. XGBoost
5. LightGBM
6. CatBoost

Each family gets its own persistent Optuna TPE study. The default budget is 30 trials per family (180 total candidate configurations), overridable with `EXP2_M2_TRIALS`.

Each study begins with a known baseline configuration before TPE exploration.

## Purged chronological CV

Search uses expanding 2024 validation blocks of two months each. For every block:

- training uses only earlier events,
- a 120-minute purge gap is applied,
- training events must have resolved (`exit_time`) before validation begins,
- no future validation block participates in the fit.

This creates six chronological validation folds across 2024 while 2023 provides the initial training history.

## Optimization objective

M2 does not optimize AUC alone. The robust objective combines:

- mean ROC AUC edge above random,
- average-precision lift over class prevalence,
- top-decile economic-success lift,
- average top-decile realized net return,
- worst-fold top-decile realized net return,
- penalties for AUC instability,
- penalties for top-tail return instability,
- a penalty if any validation fold falls below random AUC.

All of these objective terms are computed only inside purged 2024 folds.

## Heterogeneous finalist ensemble

One winner is retained per family. The strongest four distinct family winners become finalists.

The finalists are then rebuilt across the same purged folds to generate strictly out-of-fold probabilities. A small regularized logistic blender is trained only on those OOF probabilities and simple ensemble aggregates (mean/min/max/std).

The blender never trains on ordinary in-sample base-model predictions.

Finally, each finalist is refit on all 2023-2024 events. The frozen ensemble sees 2025 only after this process is complete.

## 2025 and 2026

2025 may tune only one execution dimension: five predeclared causal rolling percentiles of the frozen M2 score (90%, 92.5%, 95%, 97.5%, 99%). The same conservative deployment gate from EXP-2-M1 is retained.

After the 2025 rule is selected and frozen, 2026 is the historical shadow test. Because 2026 has already been inspected by earlier research trees, it is not globally pristine evidence.

## Workflow

```bash
pip install -r requirements-exp2-m2.txt
python train_exp_2_m2.py
python tune_exp_2_m2.py
python backtest_exp_2_m2.py
```

Do not modify M2's model search, objective, hyperparameters or execution family after its 2025/2026 results are observed. A material change becomes EXP-2-M3.
